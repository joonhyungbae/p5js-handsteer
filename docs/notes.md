# 만들면서 생각한 것

[README](../README.md) 에서 옮겨 둔 설명입니다. 코드를 돌려 본 다음에 읽으면 좋습니다.

아래의 판단들은 멘토링에서 한 작업을 돕는 과정에서 나온 것입니다.

## 왜 브라우저 하나인가

처음에는 감지는 브라우저, 그림은 유니티, 소리는 에이블톤으로 나누는 길을 봤습니다. 작품을
만드는 동안에는 괜찮지만 전시장에서는 프로그램이 셋이 됩니다. 아침마다 셋을 순서대로 켜야 하고,
하나가 멈추면 나머지가 멀쩡해도 작품이 멈춥니다. 노트북 한 대로 셋을 같이 돌리는 부담도 있습니다.

그래서 한 브라우저 안에서 감지·그림·소리를 모두 하도록 두었습니다. 켜는 것은 한 번이고,
멈추면 새로 고침 한 번입니다. 다른 도구로 넘기고 싶을 때를 위해 OSC 와 JSON 은 남겨 두었지만
쓰지 않아도 작품이 성립합니다.

## 왜 손의 값을 몸 크기로 나누는가

손목의 화면 좌표를 그대로 쓰면, 사람이 뒤로 물러서는 것만으로 값이 바뀝니다. 키가 다른 사람도
다른 값을 냅니다. 그래서 어깨 너비와 어깨에서 엉덩이까지의 길이로 나눠 둡니다. 멀든 가깝든,
키가 크든 작든 「어깨보다 이만큼 위」가 같은 숫자가 됩니다.

## 왜 그리는 자리와 고르는 자리를 갈라 두었나

`steer.js` 는 손의 뜻을 정하고, `sketch.js` 는 그 뜻으로 그림을 그립니다. 둘을 한 파일에 두면
그림을 바꾸다 조작이 틀어지고, 조작을 고치다 그림이 깨집니다. 갈라 두면 한 번에 한 가지만
바꿀 수 있습니다.

## 왜 문장을 파일로 적지 않는가

관객이 보낸 문장은 켜 있는 동안만 메모리에 둡니다. 전시가 끝나면 사라지고, 서버를 다시 켜면
빈 화면에서 시작합니다. 남겨 두면 누가 언제 무엇을 적었는지가 기록으로 쌓이고, 그 기록을
어떻게 다룰지가 작품과 별개의 문제가 됩니다. 남겨야 할 작업이라면 적는 자리를 따로 만들고,
관객에게 남는다고 먼저 알리는 편이 맞습니다.

## 이 예제가 하지 않는 것

- 한 번에 한 사람만 봅니다. 여럿이 서면 가장 크게 잡힌 사람을 따릅니다.
- 손가락을 보지 않습니다. 주먹을 쥐었는지 폈는지는 알 수 없습니다. 시작 신호를 두 손을 드는
  것으로 둔 이유입니다. 멀리서도 안정적으로 잡히기 때문입니다.
- 전시장에서 하루 종일 혼자 도는 준비(자동 시작, 멈췄을 때 다시 켜기)는 들어 있지 않습니다.

## 여기서 물어볼 것

- 관객이 설명 없이 조작법을 알아챌 수 있는가. 못 알아채면 무엇을 보여 줘야 하는가.
- 관객이 적은 문장이 화면에 그대로 떠오릅니다. 장난으로 적은 문장이 섞일 때 어떻게 할 것인가.
- 손을 계속 들고 있으면 팔이 아픕니다. 몇 분이 한계인가.
- 조작이 잘되는 것과 작품이 좋은 것은 다릅니다. 둘 중 무엇을 고를 것인가.
